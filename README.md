# האתר העצמאי

גרסה של הלוח שרצה כאתר רגיל, מנותקת לגמרי ממערכת המשרד ומהארטיפקט.

**למה בכלל:** בתוך הארטיפקט של claude.ai הדפדפן חוסם כל קריאת רשת חיצונית, ולכן אי אפשר לדבר עם Supabase. מחוץ לו אין חסימה, והסימונים נשמרים במסד אמיתי ומשותפים לכולם.

## מה יש כאן

| קובץ | תפקיד |
|---|---|
| `index.html` | האתר עצמו, נבנה מ-`board.html` על ידי `scripts/build-site.js` |
| `config.example.js` | תבנית להגדרות. להעתיק ל-`config.js` ולמלא |
| `schema.sql` | טבלת הסימונים והרשאות הגישה |

`config.js` **לא נמצא כאן בכוונה**, כדי שלא ייכנס לגיט בטעות. מעתיקים אותו מהדוגמה.

## הקמה, שלוש פעולות

**1. פרויקט Supabase חדש.** לא לחבר לפרויקט של peopleApp. אחרי היצירה, ב-SQL Editor, להריץ את `schema.sql`.

**2. הגדרות.** ב-Project Settings, ואז API, יש שני ערכים:
- Project URL
- מפתח anon public

להעתיק `config.example.js` ל-`config.js` ולמלא אותם. המפתח הזה נועד לשבת בדפדפן ואינו סוד. מה שמגן על הנתונים הוא ה-RLS.

**3. העלאה.** התיקייה סטטית לגמרי, שני קבצים. אפשר לגרור אותה ל-Vercel, ל-Netlify או לכל אחסון סטטי. אין שלב בנייה ואין תלויות.

## עדכון שבועי

אחרי כל רענון של הלוח:
```bash
node scripts/build-board-data.js
node scripts/build-site.js
```
ואז מעלים מחדש את `site/index.html`. `config.js` לא משתנה.

**היתרון על הארטיפקט:** אין נעיצת גרסה. מי שנכנס רואה תמיד את מה שהעלית אחרון.

## מה שכדאי לדעת על ההרשאות

הטבלה פתוחה לקריאה, לכתיבה ולמחיקה לכל מי שיש לו את כתובת האתר. זו החלטה מודעת לחבורה סגורה: אין כאן נתונים רגישים, רק שמות פרטיים של ילדים ומזהי אירועים.

המשמעות המעשית: מי שיש לו את הקישור יכול גם לבטל סימון של אחר. בקבוצה של כמה משפחות זה לא תרחיש אמיתי. אם הלוח יגדל, השלב הבא הוא הזדהות קלה, למשל קוד קבוצה, ואז לצמצם את מדיניות המחיקה.
